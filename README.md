# ♠️ Poker Monte Carlo

Сервис поддержки принятия решений в Texas Hold'em на основе метода Монте-Карло.

## 📌 Идея

Пользователь передаёт состояние текущей покерной раздачи:
- две карты игрока (hole cards);
- количество противников;
- открытые карты стола (community cards);
- параметры текущей ставки (размер банка, размер ставки для колла).

Сервис моделирует большое количество возможных продолжений раздачи и оценивает:
- вероятность победы (Win);
- вероятность ничьей (Tie);
- вероятность поражения (Loss).

На основании заданной стратегии и математического ожидания (EV) сервис формирует рекомендацию:
- **RAISE** — повысить ставку;
- **CALL** — продолжить с текущей ставкой;
- **FOLD** — сбросить карты.

---

## ⚙️ Как это работает

1. **Текущее состояние раздачи** → получение входных данных от пользователя.
2. **Генерация случайных вариантов** → добросовестное случайное заполнение неизвестных карт колоды.
3. **Моделирование большого количества раздач** → симуляция N итераций (например, 10 000 – 100 000) до конца раздачи.
4. **Определение победителя каждой раздачи** → оценка силы 7-карточных комбинаций для каждого игрока.
5. **Расчёт статистики** → агрегация процентов побед, ничьих и поражений, расчёт EV.
6. **Рекомендация игроку** → вывод оптимального действия на основе пороговых значений стратегии.

---

## 🃏 Этапы Texas Hold'em

Раздача проходит по классическим этапам, и вероятность может быть пересчитана после каждого из них:
1. **Preflop** — игрок получает две закрытые карты.
2. **Flop** — открываются три общие карты стола.
3. **Turn** — открывается четвёртая общая карта.
4. **River** — открывается пятая общая карта.

## 🛠 Рекомендуемый стек технологий

Поскольку основная нагрузка ложится на быстрые вычисления, стек оптимизирован для производительности и удобства разработки.

### Backend & Core
- **Python 3.11+** — основной язык разработки.
- **FastAPI** — высокопроизводительный веб-фреймворк для создания API (с поддержкой асинхронности).
- **Pydantic** — валидация входных данных и сериализация ответов (встроена в FastAPI).
- **NumPy** — векторизованные вычисления для ускорения генерации случайных чисел и матричных операций при симуляции.
- **Numba** или **Cython** — JIT-компиляция критических участков кода (оценка комбинаций и циклы симуляции) для достижения скорости, близкой к C++.
- **Treys** или **Pypokerengine** — открытые библиотеки для сверхбыстрой оценки силы покерных комбинаций (7 карт).

### Инфраструктура и DevOps
- **Docker** & **Docker Compose** — контейнеризация приложения для лёгкого развёртывания.
- **Redis** — кэширование результатов для часто встречающихся префлоп/флоп ситуаций (например, стандартные диапазоны), чтобы не прогонять симуляцию заново.
- **PostgreSQL** (опционально) — для логирования запросов и аналитики использования сервиса.
- **GitHub Actions** — CI/CD пайплайны для автоматического тестирования и деплоя.

### Тестирование
- **pytest** — фреймворк для модульного и интеграционного тестирования.
- **Hypothesis** — property-based тестирование для проверки корректности генерации колоды и граничных условий.

## 🔌 Внешние API и интеграции

Для расширения функциональности, тестирования и валидации моделей рекомендуется интегрировать следующие внешние API:

1. **[Deck of Cards API](https://deckofcardsapi.com/)**  
   *Зачем:* Идеально подходит для этапа разработки и тестирования. Позволяет эмулировать перемешивание колоды, выдачу карт и проверку логики работы с состоянием колоды без написания собственного генератора на ранних этапах.

2. **[GTO Wizard API](https://gtowizard.com/) (или аналоги)**  
   *Зачем:* Для валидации рекомендаций. Сравнение результатов симуляции Монте-Карло с эталонными Game Theory Optimal (GTO) решениями поможет калибровать стратегию и повышать точность советов (особенно на префлопе и флопе).

3. **[The Odds API](https://the-odds-api.com/)**  
   *Зачем:* Если сервис планируется интегрировать с реальными данными покер-румов или турниров, этот API предоставит актуальные коэффициенты и данные о ставках, что позволит обогащать расчёт математического ожидания (EV) реальными рыночными данными.

4. **Microservice Hand Evaluator (на базе открытого кода)**  
   *Зачем:* Развёртывание отдельного легковесного микросервиса (например, на C++ или Rust с Python-обёрткой), который принимает 7 карт и возвращает ранг комбинации. Это снимет нагрузку с основного FastAPI-приложения и обеспечит максимальную скорость оценки миллионов рук в секунду.
