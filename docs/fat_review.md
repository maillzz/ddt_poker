# Разбор «толстой» view: `web/views_fat_example.py`

Функция `fat_integrate` (не подключена к `urls.py`) считает интеграл методом трапеций прямо в обработчике
запроса. В ней смешаны все слои: HTTP, валидация, расчёт и работа с БД. Ниже — 5 проблем, у каждой:
где она, что произойдёт и куда перенести.

Слои проекта (AGENTS.md): **view/API** — только приём и ответ → **`web/services.py`** — статусы и запись задачи →
**`core/`** — чистый расчёт `run(params) -> dict`. Вход проверяет pydantic-схема **до** расчёта.

## 1. `eval()` выполняет любой текст из адреса — строка 18

```python
f = eval(fn, {"sin": math.sin, "cos": math.cos})
```
`fn` берётся из `?f=...` без проверки. Ограничение `{"sin", "cos"}` не спасает: через `__builtins__` и
`().__class__.__mro__` в `eval` можно добраться до `os` и выполнить посторонний код на сервере
(чтение `.env` с `SECRET_KEY`, удаление файлов). AGENTS.md, правило 4: никакого `eval`/`exec` на пользовательских строках.

**Куда перенести:** в `core/schemas.py` — список разрешённых функций (`Literal["sin", "cos"]`),
в ядре — словарь `{"sin": math.sin, "cos": math.cos}` и выбор функции по имени. Всё остальное — ответ **422**.

## 2. Расчёт прямо в обработчике запроса — строки 19–23

```python
h = (b - a) / n
s = 0.5 * (f(a) + f(b))
for i in range(1, n):
    s += f(a + i * h)
```
Вычисление живёт во view: его нельзя проверить эталонным тестом без HTTP, нельзя вызвать из API, формы,
CLI (`python -m core`) или воркера очереди — пришлось бы копировать.

**Куда перенести:** в ядро `core/` — функция `run(params: dict) -> dict` без Django.
View остаётся только приём параметров и ответ.

## 3. Плохой ввод не проверяется → 500 или тихо неверный ответ — строки 15–17, 19

| Ввод | Что происходит | Ответ |
|------|----------------|-------|
| `?n=0` | `h = (b - a) / n` → `ZeroDivisionError` | **500** |
| `?a=abc` | `float("abc")` → `ValueError` | **500** |
| `?n=abc` | `int("abc")` → `ValueError` | **500** |
| `?n=-5` | цикл не выполняется, ошибки нет | **200** с бессмысленным числом |

Пользователь вместо понятной ошибки получает «сервер упал» (а при `DEBUG=1` — трейсбек с путями и настройками).
Отрицательное `n` хуже всего: ошибки нет, но ответ неверный.

**Куда перенести:** в `core/schemas.py` — pydantic-схема: `a: float`, `b: float`, `n: int = Field(ge=1, le=...)`,
`f: Literal["sin", "cos"]`. Валидация — до расчёта, плохой ввод → **422** с объяснением, что не так.

## 4. View сама пишет задачу в БД — строки 24–25

```python
t = Task(name="fat", params={"f": fn}, status="done", result={"value": value})
t.save()
```
- Нарушено правило слоёв: статусы задачи меняются **только** в `services.execute_task` / `jobs.enqueue_task`
  (AGENTS.md, правило 3). Здесь view обходит сервис.
- `status="done"` — такого статуса нет в `Task.STATUS_CHOICES` (`PENDING/RUNNING/FINISHED/FAILED`):
  страница задачи и API не узнают такую задачу.
- `params={"f": fn}` — сохранены не все параметры (`a`, `b`, `n` потеряны): расчёт не воспроизвести.
- Нет `owner`: задача ничья, её не видит ни один пользователь.

**Куда перенести:** в `web/services.py` — `services.create_and_run(name, params, owner=request.user)`:
сервис создаёт задачу, ведёт статус `PENDING → RUNNING → FINISHED/FAILED` и сохраняет результат.

## 5. Тяжёлый расчёт синхронно, без предела — строки 17, 21–22

Верхней границы `n` нет. Замер цикла (функция `sin`): `n = 5 000 000` — 0,55 с, значит
**`n = 50 000 000` — ~5,5 с ожидания страницы**, `n = 5 000 000 000` — ~10 минут. Всё это время:
- браузер висит, а прокси/gunicorn обрывает запрос по таймауту (обычно 30–60 с) — результат теряется;
- воркер сервера занят одним запросом; несколько таких запросов кладут сервис (DoS одной ссылкой).

**Куда перенести:** предел `n` — в схему (`le=...`, иначе 422). Сам расчёт — в фон: view отвечает сразу
`202 {"id": ...}`, а расчёт идёт в фоновом потоке или очереди RQ (`create_and_run`, см. ADR-002);
клиент забирает статус `GET /api/tasks/{id}` и результат `GET /api/tasks/{id}/result`.

---

**Ещё замечание:** view доступна без входа — нет `@login_required`, любой аноним запускает расчёт.

**Итог рефакторинга:** `view → schema (422) → services.create_and_run → [фон] core.run → Task.result`.
Именно так устроен основной путь проекта: `web/views.py:task_create` и `api/api.py:create_task`.
